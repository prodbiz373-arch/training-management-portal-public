## 7. 画面間・API・DBの整合性

- スケジュール名はscheduleの単一値を更新し、一覧・詳細・Home・Progressが参照する。名称の複製同期を新規追加する必要はない（OK-01）。
- 課題対象はtask_flg=1。内容NULLの通常研修を新規課題に数えない設計。空欄＋課題ONはService検証、課題解除は全受講者の実績で保護する。DB CHECKに内容と課題の組合せ条件があるとは記載しない（DIFF-01～03）。
- 提出状況なしは仮想未提出。参照GETにINSERTはなく、Progress書き込み時に初めて生成する。CRUD設計をDIFF-26で確定する。
- コメント編集は本人＋canComment、削除は本人＋課題閲覧権限。講師の編集権限喪失後は編集不可でも本人削除可能であり、両者を一律条件にしない。

- 所有者/ACL/実データの現時点の一致は今回DBに接続して確認していない。V4後の状態は既存の適用報告に基づく。SQLの最終定義と既存報告を、今回取得したDB証跡として扱わない。
