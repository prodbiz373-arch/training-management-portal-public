# Excel旧画面画像の差し替え準備計画（2026-10-18）

## 1. 結論

旧画像41点を全件「差し替え候補」とする。現在の基本詳細設計書のZIP内部パート、シート、Drawing、図形IDと旧イベント表示を対応付けた。今回はExcel・画像を変更しない。テーブル定義書に画像はなく、本計画の41点はすべて基本詳細設計書内にある。

## 2. 根拠と限界

- workbook→worksheet→drawing→imageのRelationshipをたどり、画像の対応を確認した。画像ファイル名だけでシートを推測していない。
- 旧41点はすべてJPEG、更新済み11点はPNG。全52点の対応を取得し、JPEGの41点を対象とした。
- Gitコミット8c431972（2026-09-13）、e76648cf（2026-10-12）内の基本詳細設計書と比較し、旧41点は全件同一バイトである。したがって最新の実ブラウザ検証で撮り直された画像ではない。
- design-final-update-report.mdに合成API/隔離実APIで撮影した根拠があるのは更新済み11点。旧41点の撮影元、合成アカウント、fixture、撮影ログを一対一で保証する記録は、参照資料と今回のリポジトリ調査から確認できなかった。
- 旧画面のモック風のイベント札やコード風IDは、合成データを示唆するだけで実在性否定の証明ではない。氏名/IDの値を根拠なく架空と認定しない。
- 旧41点は前回のコンタクトシート目視と現在の同一性を確認した。氏名/社員ID候補はあるが、メール/秘密値の明白な表示は確認していない。全小文字の原寸検査や本人照合は未実施。
- 表の「再撮影可能」は現行ソースとAPIを参照した静的な実現性判断。今回ブラウザ・DBを起動していないので撮影成功を意味しない。

## 6. 推奨する撮影・差し替え手順（今回は未実行）

1. Git管理外へExcelのバックアップを取得し、SHA-256とZIPパート構造を記録する。
2. 開発DBを使わず、独立したPostgreSQLと合成アカウント/研修だけを準備する。表示確認用にAPIをstub化した場合は実DB/E2E撮影と混同せず記録する。
3. Chromeの新規専用プロファイルとCDP等を使用し、OSの画面収録やアクセシビリティ権限を使わず撮影する。パスワード欄は空の入力例か伏字にし、Cookie/ヘッダー/個人プロファイルを写さない。
4. manifestに画像ID・イベント・合成fixtureの識別子・撮影条件・実API/stubの別・SHA-256を記録する。秘密値や実社員名は書かない。
5. 41枠のうち同じ基礎画面は新しい同一素材を再利用できるが、イベント説明と状態が一致することを確認する。41回の独立撮影を機械的に要求しない。
6. 自己登録誘導や専用戻るボタン等の廃止済み説明は、現行確定仕様に沿ってキャプション修正案をレビューしてから反映する。画像だけ差し替えて旧説明を残さない。
7. 新画像を目視/メタデータ検査した後、限定したZIPパートだけを差し替える。JPEG→PNGの形式変更時は拡張子・Content Types・relsを整合させる。既存図形/アンカー/印刷レイアウトを保持する。
8. 全49シート、画像52枠、数式215件、セル結合、図形、リンク、印刷設定を比較し、Microsoft Excelで表示・印刷を確認する。確認できない部分は未確認とする。

現時点では撮影も差し替えも行っておらず、基本詳細設計書の分類は「修正後公開」を維持する。旧画像の実在性が後から確認できた場合は、公開許諾または合成撮り直しの判断を別途行う。履歴内の同じ画像も残るため、現在の画像差し替えだけで全履歴の問題が解決するわけではない。
