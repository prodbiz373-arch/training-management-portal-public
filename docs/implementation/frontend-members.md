# メンバー画面のAPI接続

既存の一覧・登録エリアのデザインを維持し、メンバー管理だけを実APIへ接続した。バックエンド仕様、DB、他機能のモックは変更していない。

| 画面操作 | API |
| --- | --- |
| 初期表示・再試行・変更後の一覧再取得 | GET /api/members |
| 行選択 | GET /api/members/{syainId} |
| 新規登録 | POST /api/members |
| 更新 | PUT /api/members/{syainId} |
| 削除確認後 | DELETE /api/members/{syainId} |

一覧はAPIの社員ID昇順を維持する。読み込み中、0件、通信失敗と再試行を表示する。選択時に詳細を再取得し、そのupdateCountで更新する。社員IDは編集不可。更新競合では編集状態を解除し、一覧を再取得して選び直してもらう。自分の社員区分変更について追加制限は設けていない。

認証は既存AuthProviderとCookieセッションを使用する。全通信でcredentials: "include"を指定し、更新系はAuthProviderの現在のCSRF情報をX-CSRF-TOKENに設定する。CSRF情報がなければ既存の取得APIで補う。操作社員IDヘッダーは送らない。監査社員IDはバックエンドが決定する。

InstructorOnlyは講師以外に一覧・編集UIを描画せず、メンバーAPIも呼ばない。バックエンドの認可が正であり、APIの401では既存の通知を通じて認証状態を破棄してログインへ戻る。403では管理画面を隠し権限不足を表示する。

登録・更新・削除の実行中は再送信を防止し、成功後はフォームを初期化して一覧を再取得する。削除確認には社員IDと氏名を表示する。204は本文を解析しない。パスワード入力は送信開始時に消去する。更新時の空欄は変更なし。パスワードをReactの一覧・編集データ、Web Storage、ログへ保存しない。APIレスポンスは5項目だけを取り出す。

400は既知の項目名と安全な検証文言だけを各入力欄に表示する。rejectedValueは取り込まない。BCryptのUTF-8で72バイトの上限はサーバーの検証結果を表示し、未確定の最小文字数・複雑性は追加しない。404は選択解除と一覧再取得、409は重複・更新競合・参照中・自己削除を区別する。500・通信エラーは固定の安全な表示とする。

## 残っているモック

portal-store、mock-dataおよびスケジュール・課題・進捗・ピン留めのモックは残している。他画面のメンバー参照も引き続きモックで、実DBと同期しない。portal-storeのメンバーCRUDはこの管理画面から呼ばない。一括削除は行っていない。

## 手動確認

1. frontend-auth.mdの手順でPostgreSQL、Spring Boot、Next.jsを起動する。環境変数でDBパスワードとAPI URLを設定する。
2. 講師でログインしてメンバー画面を開き、DBの社員ID昇順、氏名、区分を確認する。
3. 検証用メンバーを登録し、行選択から氏名変更、空パスワード更新、パスワード変更を確認する。検証用パスワードやトークンを記録・共有しない。
4. 別ブラウザーで同じメンバーを更新して競合を発生させ、編集解除と再取得を確認する。
5. 自己削除、参照中メンバーの削除で409の表示を確認する。検証用データは最後に削除する。
6. 新人でログインしてURLを直接入力し、一覧・フォームが表示されずメンバーAPIを呼ばないことを確認する。
7. セッション切れでログイン画面へ戻ること、サーバー停止時の安全なエラーと再試行、狭い画面での既存レイアウトを確認する。

Vitestでは実APIクライアントとfetchの模擬応答を使用する。実ブラウザーと実DBを跨ぐ確認は上記の手動確認が必要。未確定のパスワード規則や自己登録仕様は今回変更していない。
