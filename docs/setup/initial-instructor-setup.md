# 初期講師の安全なセットアップ（DIFF-16）

## 1. 利用条件

未ログインでの自己登録は提供しない。初期講師は管理者がローカル管理コマンドで1回だけ作成する。その後の新人・講師はログイン済み講師がメンバー管理画面で登録する。

対象スキーマのkenshu_memberが0件の場合だけ利用できる。講師がいなくても新人などの社員が1件でも存在すれば拒否する。既存社員を昇格・更新したり、パスワードをリセットしたりする機能ではない。通常起動時の自動シードもない。

DB名はtraining_portal、DBユーザーはtraining_portal_user、ホストは127.0.0.1に限定する。ポートとスキーマpublic/test1は必ず明示する。新環境用であり、既存の開発DBを初期化してはならない。

## 2. DB・Migrationの前提確認

管理者が接続先と対象スキーマを確認する。例としてpublicなら、読み取り専用接続で次を確認する。

```sql
BEGIN READ ONLY;
SELECT current_database(), current_user, current_schema(),
       host(inet_server_addr()), inet_server_port();
SELECT version, checksum, success
FROM public.flyway_schema_history ORDER BY installed_rank;
SELECT count(*) FROM public.kenshu_member;
COMMIT;
```

test1を使う場合は完全修飾名をtest1へ変更する。パスワードや社員全行を表示しない。

[新規構築手順](fresh-environment.md)に従ってV1〜V5が適用され、auth_version列を含む最新Entityの構造検証に成功する必要がある。本コマンドはFlyway・DDL・スキーマ作成を実行しない。通常設定のtarget=2も変更しない。未構築環境では先にDBとスキーマ・Migrationを準備する。

新規publicではV3のSQLがpublicを拒否するため、V1〜V5の単純な一括実行はできない。V3省略登録とV4・V5通常適用を区別した承認済み移行手順が必要。test1ではV1〜V5を通常適用できる。社員登録のために既存migrationを書き換えたりrepairしたりしない。

## 3. ビルドと登録手順

Java21でJARを作成する。以下のpackageはテストを省略するため、リリース前の関連テスト成功を別途確認する。

```sh
./mvnw -DskipTests package
```

新しいpublic環境の例：

```sh
java -Dloader.main=com.training.portal.setup.InitialInstructorCommand \
  -cp target/training-portal-0.0.1-SNAPSHOT.jar \
  org.springframework.boot.loader.launch.PropertiesLauncher \
  --initialize-first-instructor \
  --host=127.0.0.1 \
  --port=5432 \
  --database=training_portal \
  --schema=public
```

この例の5432を無確認で使用しない。隔離環境なら専用ポートとtest1等を指定する。引数の順序は上記のとおり。通常の`java -jar`は通常アプリを起動し、初期登録コマンドを自動実行しない。

専用コマンドはWebサーバー・Controller・認証APIを起動しない。通常アプリのコンポーネント走査にも初期登録Serviceを公開しない。

## 4. 対話入力

実端末で実行する。System.consoleがないパイプ・入力リダイレクト・非対話環境は拒否する。

1. 表示された接続先を確認する。
2. 例`training_portal/public@127.0.0.1:5432`をそのまま入力して確定する。
3. DBパスワードを非表示入力する。
4. 社員ID・社員名・任意のふりがなを入力する。
5. 初期講師パスワードを非表示で2回入力する。

社員区分は2固定、auth_versionの初期値は0。社員ID・氏名・パスワードの入力チェック、重複チェック、DB制約は既存メンバー登録Serviceを再利用する。BCryptPasswordEncoderの既存設定（強度10）で保存する。パスワードは必須、既存仕様どおりUTF-8で72バイト以内。別の複雑性ルールは追加しない。

パスワードをコマンド引数、環境変数の固定値、シェル履歴、SQLファイル、Gitへ書かない。DBパスワードもこのコマンドでは環境変数を使わず非表示入力する。コマンドのライブラリログは無効化し、エラー時に入力値・SQL・スタックトレースを表示しない。char配列は使用後に消去するが、既存DTO/JDBCが使うJava Stringの完全なメモリ消去までは保証できない。

## 5. 登録確認

成功メッセージと終了コード0を確認する。読み取り専用で、対象スキーマの社員件数1、該当社員のsyain_kbn=2、auth_version=0、update_count=0を確認する。password列の値そのものは表示しない。

登録は同一トランザクション内でテーブルをEXCLUSIVEロックして空判定からコミットまで行う。他の初期登録コマンドや通常INSERTと競合するため、並行実行でも初期講師は1件だけになる。ロック待機上限は5秒。既存社員・不正入力・DBエラーの場合は登録せず終了コード1を返す。

## 6. ログインと追加メンバー登録

通常アプリを新コードで起動し、初期講師の社員IDと設定したパスワードでログインする。メンバー管理画面から新人・講師を追加できることを確認する。初期登録専用のWeb APIはない。通常のメンバー登録APIはログイン済み講師とCSRFトークンを必要とする。

旧/registerへのアクセスはログイン画面へ戻る。旧ローカルモックによる登録は行わず、ログイン画面・通常メンバー画面のデザインは変更していない。

## 7. 二重実行・既存環境

対象スキーマに社員がいれば、社員IDが異なっていても初期登録を拒否する。既存社員、パスワード、ロール、認証世代を変更しない。社員を削除してコマンドを通す運用をしない。講師が不在の既存環境の復旧は、バックアップと権限を確認した別の承認作業として扱う。

本コマンドは明示的な対象指定とDBの空判定をガードとする。接続先が新環境なのかという管理者の確認そのものを代替しない。スキーマごとの空判定であり、クラスタ全体に社員が存在しないことを判定する機能ではない。

## 8. 失敗時

終了コード1なら、再実行前に接続先、V5までの適用、対象スキーマの社員件数、入力制限、ロック競合を確認する。接続できない場合に別DBへフォールバックしない。コマンドからmigration・repair・clean・既存社員更新は行わない。

通信が切れて結果が不明な場合は、読み取り専用で登録済みか確認する。登録成功済みなら追加実行は拒否される。パスワードをログへ出して調査しない。

## 9. ポートフォリオ公開時

初期パスワードや実社員情報をREADME・画面証跡・Gitへ掲載しない。公開デモの固定パスワードを本コマンドへ組み込まない。DB資格情報・ネットワークの管理権限を持つ人だけが実行できるよう運用する。このコマンドはOS管理者の権限を認証する仕組みではなく、ローカル端末とDB資格情報を管理者が適切に保護する前提である。

HTTPS・セキュアCookie等の公開環境設定は既存の運用方針に従う。初期登録のために未認証HTTP API、自己登録、CSRF無効化を公開しない。
